## Typography

This app uses a single unified 4-size, 2-weight type scale that serves both Latin (UI chrome) and Arabic (Quran text) rendering. The same size tokens apply to both scripts; the font family changes per script (system sans-serif for Latin, KFGQPC Uthmani Hafs for Arabic).

| Role | Size | Weight | Line Height (Latin) | Line Height (Arabic) | Usage |
|------|------|--------|---------------------|----------------------|-------|
| Label | 14px | 400 (regular) | 1.4 | 1.0 | Tab labels, search placeholder, secondary metadata (ayah count, revelation type), Arabic-Indic numerals inside ayah end markers (۝) |
| Body | 18px | 400 (regular) | 1.5 | 1.6 | Onboarding descriptions, settings labels, surah metadata, Arabic onboarding text, Arabic search input, Bismillah |
| Heading | 24px | 700 (bold) | 1.3 | 1.6 | Screen titles, surah list item name (English), section headers, surah name in ornamental header banner |
| Display | 28px | 700 (bold) | 1.2 | 2.2 | Onboarding hero text, primary Quran text display |

**Line-height split rationale:** Latin and Arabic share the same size tokens but require different line heights due to script geometry. Arabic line heights are declared separately because (a) Uthmani script with full tashkeel (diacritics) has vertical extenders above and below the baseline that Latin does not, and (b) at Display size (28px) used for Quran body text, a 2.2 line height prevents diacritical marks from one line colliding with marks on the adjacent line. Standard 1.5 causes visual collision of vowel marks. The Latin line heights follow conventional web/mobile typographic ratios.

**Weight usage:**
- 400 (regular): All body text, labels, and all Arabic text at Body and Label sizes
- 700 (bold): Headings (screen titles, surah names in list) and Display (onboarding hero, Quran body text)

**Quran body text note:** Quran text renders at Display size (28px) with weight 700. In the KFGQPC Uthmani Hafs font, "bold" weight does not produce a heavy appearance — it produces the standard mushaf stroke weight that readers expect. This weight maps to the font's primary face. If the bundled font file only includes a single weight, NativeWind/React Native will render the available weight regardless of the declared value. The 700 declaration ensures that if a multi-weight font is used in the future, Quran text remains visually prominent.

**Text alignment:** Quran body text is right-aligned with `writingDirection: 'rtl'` set on all Arabic text containers. Do NOT use justified alignment — Arabic word spacing with NativeWind/React Native text layout produces inconsistent kashida and gaps that look worse than ragged-left.

**Text direction:** All Quran text containers must set `writingDirection: 'rtl'` explicitly. The app overall uses LTR layout direction (for English chrome). Only text containers with Arabic content switch to RTL.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #FAF8F2 (warm cream) | Screen backgrounds, reader background, onboarding backgrounds |
| Secondary (30%) | #FFFFFF (white) | Surah list cards, navigation bar background, search bar background, bottom tab bar background |
| Accent — Teal (interactive, ~7%) | #0D7377 (deep teal) | See reserved list below |
| Accent — Gold (ornamental, ~3%) | #C9A84C (gold) | See reserved list below |
| Text — Primary | #1A1A2E (near black) | Body text, headings, surah names |
| Text — Secondary | #6B7280 (gray-500) | Metadata labels, ayah counts, revelation type, placeholder text |
| Text — Disabled | #9CA3AF (gray-400) | Disabled button labels, inactive tab text |
| Destructive | #DC2626 (red-600) | Error states only (no destructive user actions in Phase 1) |
| Selected range | #0D737720 (teal at 12% opacity) | Background highlight on selected ayah range |
| Divider | #E5E2DA (warm gray) | Subtle horizontal rules between surah list items |

### Accent reserved-for lists

**Teal (#0D7377) is reserved for:**
- "Start Practice" CTA button (filled background)
- Tab bar active tab indicator and icon
- Selected/active surah in list (text color)
- Search bar focus border
- Ayah tap selection indicator (left border on selected ayah)
- Resume reading floating action button
- Onboarding "Get Started" button

**Gold (#C9A84C) is reserved for:**
- Ornamental ayah end markers (۝ and numeral)
- Surah header banner decorative frame/border
- Ornamental geometric accents on surah header
- Onboarding illustration accent strokes
- Bismillah decorative elements

**Gold must NEVER appear on:** buttons, navigation elements, cards, text links, form inputs, or any interactive element. Gold is purely ornamental.

### Component Interaction Details

**AyahText tap-to-select flow:**
1. User taps first ayah -- AyahText transitions to `selected-start` state (teal left border, subtle teal background tint at 12% opacity). RangeSelectionBar slides up from bottom showing "Ayah X selected -- tap another ayah to set range end."
2. User taps second ayah -- second AyahText transitions to `selected-end`. All ayahs between start and end transition to `in-range` (same teal tint). RangeSelectionBar updates to show "Ayahs X-Y selected" with a "Start Practice" button and a "Clear Selection" text button.
3. User taps "Clear Selection" -- all ayahs return to default. RangeSelectionBar slides down.
4. User taps "Start Practice" -- currently a no-op stub in Phase 1 (recitation is Phase 3). Show a brief toast: "Recitation coming soon."

**SurahListItem layout:**
- Left: Surah number in a diamond/rotated square ornamental frame (gold border, 36x36px)
- Center: Surah name in Arabic (Heading weight, primary color) on top, English transliteration name below (Label size, secondary color)
- Right: Ayah count + revelation type (Label size, secondary color, right-aligned)
- Height: 72px minimum, vertically centered content
- Divider: 1px warm gray (#E5E2DA) below each item, indented 16px from left

**BottomTabBar:**
- 2 tabs: Home (house icon) and Settings (gear icon)
- Active tab: teal icon + teal label text
- Inactive tab: gray-400 icon + gray-400 label text
- Background: white with top border 1px #E5E2DA
- Height: 56px (plus safe area inset on iOS)

## Loading & Transition States

| State | Behavior |
|-------|----------|
| App launch → Home screen | Show splash screen (Expo default) until surah list data is ready from SQLite. Target: under 500ms. |
| Home screen → Quran Reader | Navigate immediately. Show loading skeleton (3 shimmer blocks matching ayah text shape) while querying SQLite for surah text. Target: under 200ms. |
| Quran Reader scroll | Pre-load next 20 ayahs beyond current viewport using FlashList's `estimatedItemSize` and `onEndReachedThreshold`. No loading indicator during scroll. |
| Search input | Debounce 300ms. Filter surah list locally (no network). Show results instantly after debounce. No spinner needed. |
| Onboarding swipe | Horizontal swipe gesture with spring animation (Reanimated). Page dots update synchronously with gesture. |

### Loading Skeleton Design

Loading skeletons use 3 rectangular blocks with rounded corners (8px radius) stacked vertically with 12px gaps:
- Block 1: 100% width, 20px height (simulates a full-width ayah line)
- Block 2: 85% width, 20px height (simulates a shorter line)
- Block 3: 60% width, 20px height (simulates end of ayah)

Background color: #E5E2DA (divider color). Shimmer animation: linear gradient sweep from left to right, 1.5s duration, infinite loop. Use `react-native-reanimated` for 60fps shimmer.

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Minimum touch target | 44x44px on all tappable elements |
| Color contrast — text on cream | #1A1A2E on #FAF8F2 = 14.5:1 ratio (passes AAA) |
| Color contrast — teal on white | #0D7377 on #FFFFFF = 5.0:1 ratio (passes AA) |
| Color contrast — gold on white | #C9A84C on #FFFFFF = 2.6:1 ratio (FAILS — gold is decorative only, never used for text or interactive labels) |
| Screen reader | All SurahListItems announce: "Surah {name}, {ayah count} ayahs, {revelation type}" |
| Screen reader | AyahText blocks announce full ayah text with ayah number |
| RTL support | Arabic text containers use `writingDirection: 'rtl'`. App layout remains LTR for English chrome. |
| Reduced motion | Respect `AccessibilityInfo.isReduceMotionEnabled`. Disable shimmer animation and onboarding swipe spring. Use instant transitions instead. |
