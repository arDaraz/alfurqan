# Phase 01.1: QCF Mushaf Page Renderer — Context

## Problem

The Phase 01 Quran reader renders ayahs as flowing text with ragged line widths (see screenshot feedback from device testing). A proper Mushaf has uniform-width lines — 15 lines per page, 604 pages — achieved through centuries-old calligraphic tradition. The app needs pixel-perfect Mushaf rendering to match the printed Madani Mushaf (King Fahd Complex edition).

## Goal

Replace the current flowing-text `QuranReader` component with a page-based Mushaf renderer using QCF (Quran Complex Font) v2 page fonts rendered in WebViews, with horizontal RTL page swiping.

## Scope

This phase ONLY changes the Quran reader rendering. It does NOT touch:
- Home screen (surah list, juz list, search)
- Onboarding flow
- Settings
- Navigation routing structure

## Dependencies

- Phase 01 must be complete (it is — all 5 plans executed)
- quran.com API v4 (build-time only, for seeding word data)
- QCF v2 font CDN (build-time only, for downloading font files)

## Requirements

From the original Phase 01 requirements that this directly improves:
- QTEXT-01: View full Quran in Uthmani script with proper Arabic diacritics → QCF gives pixel-perfect calligraphy
- UI-01: Polished, reverent design → Mushaf page layout is the gold standard

<decisions>

### Key Decisions (already validated with user)

1. **QCF v2 fonts over alternatives**: 604 page-specific fonts where each word is a single calligraphic glyph. Pixel-perfect match to printed Madani Mushaf. Chosen over: word-per-line Unicode justification (95% fidelity), page images (no interactivity), DigitalKhatt/Skia (too complex).

2. **WebView rendering**: QCF fonts designed for web rendering. `code_v2` glyph codes work reliably with `innerHTML` in browsers. More reliable than React Native native `<Text>` for these special PUA Unicode characters.

3. **Horizontal swipe (RTL)**: Book-like page turning. Swipe left = next page (higher page number). One page at a time. Using `react-native-pager-view`.

4. **Surah entry point preserved**: Home screen unchanged. Tapping a surah opens the Mushaf at that surah's starting page. Same for Juz tap.

5. **Ayah selection deferred**: Focus on pixel-perfect rendering first. Tap-to-select ayah range is a Phase 3 concern (recitation loop).

6. **Font storage in SQLite**: Store base64-encoded WOFF2 fonts in a `qcf_fonts` table. Avoids cross-platform file:// URI issues in WebView. Each font ~15KB base64 = ~9MB total for 604 pages.

</decisions>

## Data Layer Changes

### New `mushaf_words` table (~77,000 rows)

Seeded from quran.com API v4 `/verses/by_page/{page}?words=true`.

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER PK | Auto-increment |
| surah_number | INTEGER | 1-114 |
| ayah_number | INTEGER | Verse number within surah |
| word_position | INTEGER | Word position within ayah |
| page_number | INTEGER | Mushaf page 1-604 |
| line_number | INTEGER | Line on page 1-15 |
| code_v2 | TEXT | QCF v2 glyph code |
| char_type | TEXT | "word", "end", "pause" |

### New `qcf_fonts` table (604 rows)

| Column | Type | Description |
|--------|------|-------------|
| page_number | INTEGER PK | 1-604 |
| font_data | TEXT | Base64-encoded WOFF2 font file |

### New repository functions

- `getWordsByPage(pageNumber)` — words ordered by line_number, position
- `getPageForSurah(surahNumber)` — starting page number for a surah
- `getPageForJuz(juzNumber)` — starting page number for a juz
- `getQcfFont(pageNumber)` — base64 font data

## Rendering Architecture

### MushafReader (new container component)

- `react-native-pager-view` for horizontal RTL page swiping
- 604 total pages, only 3 mounted at a time (current +/- 1) via `offscreenPageLimit={1}`
- Page indicator showing current page / 604
- Auto-saves current page to `readingStore` on page change

### MushafPage (new single-page component)

- `react-native-webview` rendering generated HTML string
- HTML includes `@font-face` with base64 data URI for page's QCF font
- 15 `<div class="line">` elements with justified CSS
- Surah headers and bismillah are part of QCF glyph data (no separate components)

### mushafHtml.ts (new HTML template generator)

- Groups words into lines
- Generates complete HTML with embedded font and styled lines

### useMushafPage.ts (new hook)

- Fetches words + font for a page from SQLite
- Generates HTML
- Caches recent pages in memory (max 10)

## Navigation Flow

1. Surah tap → `getPageForSurah(n)` → open MushafReader at that page
2. Juz tap → `getPageForJuz(n)` → open MushafReader at that page
3. Last read → `readingStore.lastReadPage` → open at saved page

## Bookmarking

- `readingStore` gets `lastReadPage: number | null` + `setLastReadPage(page)`
- Auto-saves on every page swipe
- Surah re-open restores to saved page if within that surah's range

## New Dependencies

- `react-native-pager-view` — horizontal page swiping with RTL support
- `react-native-webview` — QCF font rendering in HTML
