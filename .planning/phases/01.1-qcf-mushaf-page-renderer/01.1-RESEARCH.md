# Phase 01.1: QCF Mushaf Page Renderer — Research

## Traditional Mushaf Layout (Madani / King Fahd Complex Edition)

The printed Madani Mushaf (calligrapher: Uthman Taha, publisher: King Fahd Complex) has:
- **604 pages** total
- **15 lines per page** (standard "Madani 15-line" layout)
- Every line is **exactly the same width** — full justification, edge to edge
- Text flows continuously; a single line often contains words from **multiple ayahs**
- A single ayah can span **multiple lines and multiple pages**
- Surah headers and Bismillah occupy dedicated lines (`line_type`: surah_name, basmallah)
- Some lines are centered (surah headers), controlled by an `is_centered` flag

This layout is sacred to huffaz (memorizers) — they develop spatial memory of where each word appears.

## Approaches Evaluated

### Approach A: Pre-Rendered Page Images
- 604 PNG/JPG images scanned from printed Mushaf
- Used by: Quran Android, Open-Mushaf Native
- Rejected: +100-200MB app size, no text interaction, not accessible

### Approach B: QCF (Quran Complex Font) — SELECTED
- 604 font files, one per Mushaf page
- Each word is a **single glyph** in the page's font
- `code_v2` Unicode characters from quran.com API map to glyphs
- Rendering via HTML + CSS: `font-family: 'QCF_P{page}'` with `code_v2` text
- **~10MB** for all 604 fonts (WOFF2)
- Used by: quran.com website, react-native-quran-hafs, Flutter qcf_quran

### Approach C: Pre-Paginated Word-by-Word with Unicode Font
- Single font (KFGQPC/AmiriQuran) + word-level page/line data
- CSS `text-align: justify` or flexbox `space-between` for line width
- Rejected: 95% fidelity only, React Native `textAlign: 'justify'` has known bugs with Arabic (issue #32146)

### Approach D: Kashida/DigitalKhatt + Skia
- Variable font with dynamic letter stretching via react-native-skia
- Used by: Tarteel AI (production)
- Rejected: Requires patched Skia binaries, very high complexity

## QCF v2 Font Technical Details

### How QCF Works
- Each of 604 Mushaf pages has its own font file
- Words are encoded as **Private Use Area (PUA)** Unicode characters
- `code_v2` field from quran.com API contains these PUA characters
- When rendered with the correct page font, each character displays the calligraphic glyph
- **Must use `innerHTML`** (not `textContent`) because glyph codes contain special Unicode
- End markers (ayah numbers in ornamental circles) are included as glyphs — no custom rendering needed
- Surah headers and Bismillah are also included in the glyph data

### Font Sources
- **Quran Foundation CDN**: `https://static.qurancdn.com/fonts/quran/hafs/v2/woff2/p{page}.woff2`
- **GitHub**: nuqayah/qpc-fonts repository (TTF, WOFF, WOFF2 formats)
- **Size**: ~10-15KB per font file (WOFF2), ~10MB total

### QCF Versions
- QPC V1 (1405H print edition)
- **QPC V2** (1423H print edition, recommended — used by quran.com)
- V4 (with embedded tajweed coloring)

## Data Sources

### quran.com API v4

Endpoint: `GET /verses/by_page/{page_number}?words=true&word_fields=code_v2,line_number,page_number`

Each word object:
```json
{
  "id": 1,
  "position": 1,
  "char_type_name": "word",
  "code_v2": "ﭑ",
  "line_number": 2,
  "page_number": 1,
  "verse_key": "1:1"
}
```

- `char_type_name`: "word" (Quranic word), "end" (ayah end marker), "pause" (pause mark)
- `line_number`: 1-15 within the page
- `code_v2`: PUA Unicode character for QCF v2 font rendering
- `verse_key`: "surah:ayah" format

Pagination: `per_page=50` with `current_page`/`next_page`/`total_pages`.

### QUL (Quranic Universal Library) — qul.tarteel.ai

Alternative data source with:
- `pages` table: page_number, line_number, line_type, is_centered, first_word_id, last_word_id
- `words` table: word_index, text columns (qpc_v1, qpc_v2, etc.)
- ~9,046 page-line records for 604 pages

Not used in this implementation (quran.com API is sufficient), but available as fallback.

## React Native WebView Considerations

### Font Loading in WebView
- **Base64 data URI approach** (chosen): Embed font as `@font-face { src: url(data:font/woff2;base64,...) }`
- Avoids file:// path issues across iOS and Android
- Each font ~20KB base64 — acceptable for a single WebView load
- Store base64 in SQLite for easy retrieval

### WebView Performance
- `react-native-webview` renders WKWebView (iOS) / Android WebView
- Single HTML page per Mushaf page, no JavaScript needed
- `scrollEnabled={false}` — no scrolling within the WebView
- `javaScriptEnabled={false}` — improves security and performance
- `offscreenPageLimit={1}` on PagerView — only 3 WebViews active at a time

### Known Issues
- React Native `textAlign: 'justify'` has bugs with Arabic text (#32146) — WebView avoids this
- WOFF2 supported in all modern WebViews (Chrome 36+, iOS 10+)
- `font-display: block` prevents flash of unstyled text
